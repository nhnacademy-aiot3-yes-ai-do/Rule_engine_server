# RuleEngine 로컬 개발 환경 설정 가이드

RuleEngine을 로컬(내 컴퓨터)에서 실행하려면 MQTT 브로커에 붙어야 하는데, 이 브로커가 `s1.java21.net`이라는 우리 팀 공유 서버 안에서만 열려 있고 외부(와이파이 등)에서는 방화벽에 막혀 직접 접속이 안 됩니다. 그래서 SSH 터널을 통해 우회 접속해야 합니다.

## 왜 이렇게 해야 하나요?

- MQTT 브로커(Mosquitto)는 `s1.java21.net` 서버 안에 컨테이너(`team2-mosquitto`)로 떠 있습니다.
- 이 서버는 SSH(8822 포트)는 외부에 열려 있지만, 우리가 쓰는 MQTT 포트(10423)는 외부 방화벽에 막혀 있습니다.
- `nc -vz s1.java21.net 10423` 같은 직접 접속은 타임아웃만 나고 실패합니다.
- 대신 SSH 터널(로컬 포트포워딩)을 이용하면, 이미 열려 있는 SSH 연결을 통해 내 컴퓨터의 특정 로컬 포트를 브로커 포트에 그대로 이어줄 수 있습니다.

## 1. SSH 터널 띄우기

터미널(로컬 컴퓨터)에서 아래 명령어를 실행합니다. `<로컬포트>`는 내 컴퓨터에서 안 쓰고 있는 포트 아무거나 골라 씁니다(예: `18830`). 이미 로컬에 mosquitto를 설치해서 쓰고 계신 분은 1883은 피해주세요.

```bash
ssh -p 8822 -L <로컬포트>:localhost:10423 aiot3-team2@s1.java21.net -N -f
```

- `-N`: 원격 명령 없이 포트포워딩만 함
- `-f`: 백그라운드로 실행 (터미널 계속 쓸 수 있음)

접속 계정 정보는 팀 채널/진영에게 문의해주세요 (이 문서에는 올리지 않습니다).

### 확인

```bash
lsof -i :<로컬포트>
nc -vz localhost <로컬포트>
```

`ssh` 프로세스가 해당 포트에 `LISTEN` 상태로 떠 있고, `nc`가 `succeeded`면 터널이 정상입니다.

터널을 끄고 싶으면 `lsof -i :<로컬포트>`로 PID 확인 후 `kill <PID>`.

## 2. `.env` 파일 작성

`ruleEngine_server/.env` 파일을 만들고 아래 형식으로 채웁니다. **실제 비밀번호/토큰/URL 값은 이 문서에 없으니 팀 채널이나 기존 팀원에게 직접 받으세요.** (`.env`는 `.gitignore`에 등록되어 있어 git에는 절대 올라가지 않습니다.)

```env
REDIS_HOST=<공용 Redis 호스트>
REDIS_PORT=6379
REDIS_PASSWORD=<Redis 비밀번호>
REDIS_DATABASE=0

RABBITMQ_HOST=<공용 RabbitMQ 호스트>
RABBITMQ_PORT=5672
RABBITMQ_USERNAME=<RabbitMQ 계정>
RABBITMQ_PASSWORD=<RabbitMQ 비밀번호>

MQTT_BROKER_URL=tcp://localhost:<1번에서 고른 로컬포트>
MQTT_CLIENT_ID=mushmush-ruleengine-server-<본인이름 등으로 구분>
MQTT_USERNAME=<MQTT 계정>
MQTT_PASSWORD=<MQTT 비밀번호>

INFLUX_URL=<InfluxDB URL>
INFLUX_ORG=yes-nhn
INFLUX_BUCKET=sensor-data
INFLUX_TOKEN=<Influx 토큰>
CF_ACCESS_CLIENT_ID=<Cloudflare Access Client ID>
CF_ACCESS_CLIENT_SECRET=<Cloudflare Access Client Secret>

CULTIVATION_SERVER_URL=<cultivation-server의 접속 가능한 URL>
DATA_GENERATOR_URL=<data-generator-server의 접속 가능한 URL>
```

`MQTT_BROKER_URL`의 포트는 반드시 1번에서 SSH 터널로 연 **로컬 포트**여야 합니다. `s1.java21.net:10423`을 직접 넣으면 방화벽 때문에 타임아웃이 납니다.

`MQTT_CLIENT_ID`는 브로커 안에서 유일해야 하므로, 팀원마다 겹치지 않게 뒤에 본인 구분자를 붙여주세요 (동일 client-id로 여러 명이 동시에 접속하면 먼저 붙은 연결이 끊깁니다).

`CULTIVATION_SERVER_URL`, `DATA_GENERATOR_URL`은 Eureka 없이 각 서비스에 직접 HTTP로 붙는 Feign 클라이언트 주소입니다(재배 환경 스냅샷 조회, 액추에이터 제어 명령 전송에 사용). 로컬에서 접속 가능한 주소인지(같은 SSH 터널이 필요한지, 사설 IP인지 등)는 팀 채널에 확인하세요.

## 3. 기동 시 일어나는 일 (스냅샷 동기화)

애플리케이션이 뜰 때, `local` 프로파일이 아닌 이상(일반적인 로컬 실행은 여기 해당합니다) `cultivation-server`의 스냅샷 API를 호출해 기존에 등록된 재배 환경·센서 정보를 Redis로 가져오는 과정이 자동으로 실행됩니다. `CULTIVATION_SERVER_URL`이 잘못되었거나 해당 서버에 접속할 수 없으면, 최대 8회(지수 백오프, 최대 15초 간격)까지 재시도하다가 **애플리케이션 기동 자체가 실패**합니다. (자세한 내용은 [02_Registry/01_초기_스냅샷_동기화](../02_Registry/01_초기_스냅샷_동기화.md) 참고)

`mqtt.enabled=false`로 MQTT 연결만 끄고 싶은 경우와 달리, 이 스냅샷 동기화는 별도의 on/off 스위치가 없으므로 `CULTIVATION_SERVER_URL`은 항상 유효해야 합니다.

## 4. 실행

IntelliJ에서 `RuleEngineServerApplication` 실행 (또는 `application-dev` 프로파일로 실행). 콘솔 로그에서 아래 줄들이 에러 없이 뜨면 정상입니다.

```text
초기 registry snapshot 동기화를 완료했습니다. attempt=1
MQTT 연결 및 구독 완료 - topics=[...]
CachingConnectionFactory : Created new connection: ...
Started RuleEngineServerApplication in ... seconds
```

## 트러블슈팅

| 증상 | 원인 |
|---|---|
| `Connect timed out` | `MQTT_BROKER_URL`에 `s1.java21.net:10423`을 직접 넣은 경우. 로컬 포트(터널)로 바꾸세요. |
| SSH 터널 명령이 `Address already in use`로 실패 | 로컬 포트가 이미 다른 프로세스(로컬 mosquitto 등)에서 쓰이는 중. 다른 로컬 포트로 바꾸세요. |
| `Not authorized. (135)` | MQTT_USERNAME/PASSWORD가 비어있거나 틀림. `.env` 값 다시 확인. |
| `Connection Refused: not authorised` (mosquitto_sub/pub 테스트 시) | 위와 동일 |
| `초기 registry snapshot 동기화가 최대 시도 횟수를 초과했습니다` 로그 후 기동 실패 | `CULTIVATION_SERVER_URL`이 잘못되었거나 해당 주소에 접속 불가. URL 및 네트워크(터널 필요 여부) 확인. |
