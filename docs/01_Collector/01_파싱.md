# 01. 파싱

MQTT로 수신한 토픽·페이로드를 `SensorDataDto`로 변환하는 부분입니다. 토픽 종류별로 메세지 구조가 다르기 때문에, `SensorDataParser` 인터페이스를 두고 토픽별 구현체로 나누어 처리합니다.

## 1. SupportedTopic

```java
@Getter
@RequiredArgsConstructor
public enum SupportedTopic {

    CHIRPSTACK("application/"),
    MUSHROOM("mushroom/");

    private final String prefix;
}
```

## 2. SensorDataParser

```java
public interface SensorDataParser {

    SupportedTopic getSupportedTopic();

    boolean supports(String topic);

    List<SensorDataDto> parse(String topic, String payload);
}
```

`CollectorService`는 등록된 모든 `SensorDataParser` 구현체 중 `supports(topic)`가 `true`를 반환하는 파서를 찾아 파싱을 위임합니다. 하나의 메세지에 여러 센서 타입의 값이 동시에 담길 수 있어 반환 타입은 `List<SensorDataDto>`입니다.

## 3. SensorDataDto

```java
@Getter
@AllArgsConstructor
@ToString
public class SensorDataDto {

    private String place;
    private String location;
    private String deviceModel;
    private String deviceName;
    private String deviceEui;
    private String sensorType;
    private BigDecimal value;
    private OffsetDateTime time;
    private String unit;
    private Long cultivationId;   // 파싱 단계에서는 항상 null, 검증 단계에서 채워짐

    public SensorDataDto withCultivationId(Long cultivationId) { /* ... */ }
}
```

`cultivationId`는 파싱 시점에는 알 수 없고(토픽/페이로드 어디에도 없음), [02_검증_및_이벤트발행](./02_검증_및_이벤트발행.md)의 검증 단계에서 등록된 센서 정보를 조회해 채워 넣습니다.

---

## A. MushroomTopicParser (`mushroom/#`)

`DataSource Generator`가 발행하는 형식입니다. 토픽 문자열 자체에 센서 식별 정보가, 페이로드에 측정값이 담겨 있습니다.

```text
topic   : mushroom/{place}/{location}/{device_model}/{device_eui}/{sensor_type}
payload : {"value":..., "time":..., "unit":..., "device_name":..., "device_eui":...}
```

- 토픽을 `/` 기준으로 분리하여 `place`, `location`, `deviceModel`, `deviceEui`, `sensorType`(대문자로 정규화, `SensorTypeUtils.normalize`)을 추출합니다.
- 토픽 요소 개수가 6개가 아니면 `InvalidTopicFormatException`을 던집니다.
- 페이로드는 `value`, `time`, `unit`, `device_name`, `device_eui`를 갖는 record로 역직렬화합니다. JSON 파싱 실패, 또는 `value`/`time`/`unit` 중 하나라도 없으면 `InvalidPayloadFormatException`을 던집니다.
- 메세지 하나당 센서 타입이 하나이므로 항상 원소 1개짜리 `List<SensorDataDto>`를 반환합니다.

## B. ChirpStackTopicParser (`application/#`)

ChirpStack Network Server가 발행하는 형식입니다. 센서 식별 정보와 측정값이 모두 페이로드 안에 담겨 있습니다.

```text
topic   : application/{applicationId}/device/{deviceEui}/event/up
payload : {
  "time": "...",
  "deviceInfo": {
    "deviceProfileName": "...", "deviceName": "...", "devEui": "...",
    "tags": { "location": "...", "point": "..." }
  },
  "object": { "temperature": ..., "humidity": ..., "co2": ..., "illumination": ... }
}
```

- `deviceInfo.tags.location` → `place`, `deviceInfo.tags.point` → `location`, `deviceInfo.deviceProfileName` → `deviceModel`, `deviceInfo.deviceName` → `deviceName`, `deviceInfo.devEui` → `deviceEui`로 매핑합니다.
- `deviceInfo.devEui`가 없거나 `time` 필드가 없거나 형식(`OffsetDateTime`, 예: `2026-07-10T08:26:17.922+00:00`)이 올바르지 않으면 `InvalidPayloadFormatException`을 던집니다.
- `object` 필드는 하나의 메세지에 여러 센서 타입 값을 동시에 포함할 수 있어, 아래 매핑 테이블에 정의된 키만 걸러내어 각각 별도의 `SensorDataDto`로 변환합니다. 이때 단위는 매핑 테이블에 따라 고정으로 채워집니다.

| object 키 | SensorType | 단위 |
|---|---|---|
| temperature | TEMPERATURE | °C |
| humidity | HUMIDITY | % |
| co2 | CO2 | ppm |
| illumination | LIGHT | lux |

- 매핑 테이블에 없는 키는 무시됩니다.
- JSON 파싱 자체가 실패한 경우에도 `InvalidPayloadFormatException`을 던집니다.
