# 01. 초기 스냅샷 동기화

RabbitMQ 이벤트 구독만으로는 **"이 프로세스가 뜨기 전에 이미 등록되어 있던"** 재배 환경·센서 정보를 알 수 없습니다. RabbitMQ 이벤트는 "지금 이 순간부터의 변경분"만 담고 있기 때문입니다.

이를 위해 애플리케이션 기동 직후, `cultivation-server`의 스냅샷 API를 한 번 호출해 전체 데이터를 Redis에 채워 넣는 과정이 있습니다.

## 1. CultivationSnapshotClient

`data_generator`가 사용하는 것과 동일한 `cultivation-server` 내부 API를 재사용하는 Feign 클라이언트입니다.

```java
@FeignClient(name = "cultivation-server", url = "${feign.client.cultivation-server.url}")
public interface CultivationSnapshotClient {

    @GetMapping("/api/v1/internal/data-generator/snapshot")
    CultivationSnapshotResponse getSnapshot();
}
```

```java
public record CultivationSnapshotResponse(
        OffsetDateTime snapshotAt,
        List<CultivationSensorResponse> sensors,
        List<CultivationThresholdResponse> thresholds
) {}
```

- Eureka 디스커버리(`eureka.client.enabled: false`)를 사용하지 않고, `feign.client.cultivation-server.url`에 지정된 URL로 직접 호출합니다.

## 2. RegistrySnapshotSynchronizationService

```java
@Service
public class RegistrySnapshotSynchronizationService {

    public void synchronizeAll() {

        CultivationSnapshotResponse snapshot = cultivationSnapshotClient.getSnapshot();
        if (snapshot == null || snapshot.snapshotAt() == null) {
            throw new RegistrySnapshotSynchronizationException("Cultivation Service의 snapshot 응답이 올바르지 않습니다.");
        }

        Set<String> managedSensorTypes = new HashSet<>();

        int sensorCount = synchronizeSensors(snapshot.sensors(), managedSensorTypes);
        int thresholdCount = synchronizeThresholds(snapshot.thresholds(), managedSensorTypes);

        if (!managedSensorTypes.isEmpty()) {
            managedSensorTypeService.registerAll(List.copyOf(managedSensorTypes));
        }
    }
}
```

- `sensors` 목록의 각 센서·센서타입 조합을 `SensorInfoDto`로 변환해 `SensorInfoRepository.upsert(...)`로 저장합니다.
- `thresholds` 목록은 `cultivationId` 기준으로 그룹핑한 뒤, 재배 환경 하나당 하나의 `ThresholdInfoDto`(내부에 여러 `SensorRange` 포함)로 만들어 `ThresholdInfoRepository.upsert(...)`로 저장합니다.
- 두 목록에서 등장한 모든 `sensorType`은 `ManagedSensorTypeService.registerAll(...)`로 관리 대상 목록에도 반영합니다.
- Feign 호출 실패, 응답 형식 이상 등은 모두 `RegistrySnapshotSynchronizationException`으로 감싸서 던집니다.

## 3. RegistrySnapshotSynchronizationInitializer

애플리케이션 기동 시 `synchronizeAll()`을 호출하는 `ApplicationRunner`입니다.

```java
@Component
@Profile("!local")
public class RegistrySnapshotSynchronizationInitializer implements ApplicationRunner {

    private static final int MAX_ATTEMPTS = 8;
    private static final long INITIAL_BACKOFF_MILLISECONDS = 1000L;
    private static final long MAX_BACKOFF_MILLISECONDS = 15000L;
    private static final double BACKOFF_MULTIPLIER = 2.0;

    @Override
    public void run(ApplicationArguments args) {
        synchronizeWithRetry();
    }
}
```

- **왜 `SmartLifecycle`이 아니라 `ApplicationRunner`인가**: 컨테이너 초기 phase에 실행하면 Eureka discovery 캐시(연관 서비스인 `data_generator`의 동기화 컴포넌트 기준)가 아직 준비되지 않아 실패할 수 있어, 컨텍스트 리프레시가 완료된 뒤(`ApplicationRunner`) 실행하도록 되어 있습니다.
- **재시도**: 실패 시 지수 백오프(1s → 2s → 4s → ... 최대 15s)로 최대 8회까지 재시도합니다. 8회를 모두 실패하면 예외를 다시 던져 **애플리케이션 시작 자체를 실패**시킵니다. 동기화 없이는 기존에 등록된 센서 데이터가 영구히 누락되기 때문에, 실패한 채로 뜨는 것을 허용하지 않겠다는 의도입니다.
- **`@Profile("!local")`**: `local` 프로파일이 활성화된 경우(테스트 코드에서 `@ActiveProfiles("local")`로 사용)에는 이 초기화 컴포넌트 자체가 빈으로 등록되지 않아 동기화를 건너뜁니다. 테스트 시 `cultivation-server`에 대한 실제 네트워크 호출을 막기 위함이며, **일반적인 로컬 개발 실행(dev 프로파일 등)에서는 `local` 프로파일이 아니므로 이 동기화가 그대로 수행됩니다.** ([05_로컬개발](../05_로컬개발) 참고)

## 4. ManagedSensorTypeInitializer

```java
@Component
public class ManagedSensorTypeInitializer implements ApplicationRunner {

    private static final List<String> DEFAULT_SENSOR_TYPES =
            List.of("TEMPERATURE", "HUMIDITY", "CO2", "LIGHT");

    @Override
    public void run(ApplicationArguments args) {
        DEFAULT_SENSOR_TYPES.forEach(managedSensorTypeService::register);
    }
}
```

프로파일과 무관하게 항상 실행되며, 기본 4가지 센서 타입을 관리 대상으로 등록합니다. 스냅샷 동기화나 RabbitMQ 이벤트가 아직 한 번도 없었더라도, 이 4가지 타입에 대한 데이터는 Collector 검증(관리 대상 여부 확인)을 통과할 수 있습니다.

## 흐름 요약

```text
[애플리케이션 기동]
        │
        ├── ManagedSensorTypeInitializer.run() ── 기본 센서 타입 4종 등록 (항상 실행)
        │
        └── (local 프로파일이 아니면) RegistrySnapshotSynchronizationInitializer.run()
                │
                ├── CultivationSnapshotClient.getSnapshot()  (Feign GET, 실패 시 최대 8회 재시도)
                │
                ├── 센서 스냅샷 → SensorInfoRepository.upsert(...)
                ├── 임계값 스냅샷 → ThresholdInfoRepository.upsert(...)
                └── 등장한 모든 sensorType → ManagedSensorTypeService.registerAll(...)

[기동 이후]
        └── RabbitMQ 이벤트(threshold.*, sensor.*)로 변경분만 실시간 반영
```
