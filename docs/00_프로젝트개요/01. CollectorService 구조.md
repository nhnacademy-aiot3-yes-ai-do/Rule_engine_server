# 01. CollectorService 구조

센서로부터 발행되는 데이터를 MQTT로 구독하고, 수신한 원본 데이터를 파싱·정제하여 이후 처리에 사용할 수 있는 형태로 변환합니다.

## 구조

`CollectorService`는 실질적인 파싱·검증 로직을 직접 수행하지 않고, 아래 컴포넌트들을 순서대로 호출하여 흐름을 조율하는 역할을 합니다.

```java
// 파싱, 검증을 순서대로 호출하고, 통과한 데이터를 이벤트로 발행하는 조율자
public class CollectorService {

  // ...

  public void ingest(String topic, String payload) {
    // ex) sensorDataParser.parse(...) 호출
    // ex) sensorDataValidator.isValid(...) 호출
    // 검증 통과 시 eventPublisher.publishEvent(...) 호출
  }
}
```

### A. MQTT

모든 센서가 아래 구조로 데이터를 발행한다고 가정합니다.

```text
[예시-1 : mushroom/...]

topic :
mushroom/{place}/{location}/{device_name}/{device_eui}/{sensor_type}

payload :
{"value":...,"time":...,"device_name":...,"device_eui":...}

----------------------------------------------------------------------

[예시-2 : application/...]

topic :
application/{applicationId}/device/{deviceEui}/event/up

payload :
{
  "time": "...",
  "deviceInfo": {
    "deviceProfileName": "...",
    "deviceName": "...",
    "devEui": "...",
    "tags": {
      "location": "...",
      "point": "..."
    }
  },
  "object": {
    "temperature": ...,
    "humidity": ...,
    "co2": ...,
    "illumination": ...
  }
}
```

발행된 메세지를 MQTT 구독을 통해 수신하여 가져옵니다. 수신한 토픽과 페이로드는 `CollectorService.ingest(topic, payload)`로 전달됩니다.

상황에 따라 다음을 고려합니다.
- 토픽의 종류는 `application` 또는 `mushroom`으로 시작
  - 토픽 `mushroom/...`으로 발행되는 데이터는 `DataSource Generator`으로부터 발행되는 데이터를 의미합니다.
  - 토픽 `application/...`으로 발행되는 데이터는 `ChirpStack Network Server`로부터 수신되는 센서 장치 데이터를 의미합니다.

### B. 파싱

수신한 데이터에 대해 파싱을 수행하여 DTO로 전환합니다.
토픽 문자열에서 `place`, `location` 등을 추출하고, 페이로드(JSON)에서 `value`, `time`등을 추출하여 하나의 DTO로 합칩니다.

```java
import lombok.AllArgsConstructor;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class SensorDataDto {

    private String place;
    private String location;
    private String deviceName;

    // ...

}
```

토픽과 페이로드를 파싱하여 `SensorDataDto`로 변환하는 역할은 `CollectorService`가 주입받아 호출합니다.

```java
// 토픽 + 페이로드를 파싱하여 SensorDataDto로 변환

    public SensorDataDto parse(String topic, String payload) {

    }
}
```

### C. 정제 및 검증

수신한 메세지를 DTO로 전환한 뒤, 정제 및 검증을 진행합니다.
- 해당 `sensorType`이 관리 대상 센서 타입에 포함되는지 확인
- `value`가 존재하는지(null이 아닌지) 확인
- 해당 `device_eui`, `sensorType`, `unit`에 대응하는 센서가 실제로 등록되어 있는지 확인
- 검증에 실패한 데이터는 다음 단계로 전달하지 않고, 로그를 남긴 뒤 폐기
- 검증을 통과한 데이터에는 조회된 센서 등록 정보를 바탕으로 `cultivationId`를 채워 넣음

검증에 필요한 관리 대상 센서 타입 목록과 센서 등록 정보는 Redis 등 저장소에 보관되어 있으며, 이를 조회하여 비교합니다. `CollectorService`가 이 컴포넌트를 주입받아 호출합니다.
