# 00. 판단 흐름

Collector로부터 전달받은 센서 데이터를, 해당 재배 환경에 설정된 임계값과 비교하여 판단하는 진입점입니다.

과거에는 "DB 조회 / 노드 생성 / 이벤트 발행" 세 가지 구현 방식을 검토 중이었지만, 최종적으로 **DB(Redis) 조회 방식**으로 확정되었습니다. 판단 로직을 재배 환경 개수만큼 늘리지 않고 하나로 고정하고, 데이터가 들어올 때마다 `cultivationId`를 기준으로 Redis에 저장된 임계값을 조회해 비교합니다.

## 1. RuleEngine

```java
@Service
public class RuleEngine {

    private final ThresholdInfoService thresholdInfoService;
    private final InfluxService influxService;
    private final List<Rule> rules;

    public void start(SensorDataDto dto) {

        Optional<ThresholdInfoDto> cultivationInfoDtoOptional =
                thresholdInfoService.findCultivationInfo(dto.getCultivationId());

        if (cultivationInfoDtoOptional.isEmpty()) {
            log.warn("임계값 정보 없음 - 판단 보류: cultivationId={}", dto.getCultivationId());
            return;
        }

        publishRealTimeData(dto);

        ThresholdInfoDto thresholdInfoDto = cultivationInfoDtoOptional.get();
        rules.stream()
                .filter(rule -> rule.supports(dto))
                .forEach(rule -> rule.evaluate(dto, thresholdInfoDto));
    }

    private void publishRealTimeData(SensorDataDto dto) {
        influxService.save(SensorValueEvent.from(dto));
    }
}
```

1. `dto.getCultivationId()`로 [Registry](../02_Registry)에 캐시된 임계값 정보(`ThresholdInfoDto`)를 조회합니다. 없으면(아직 임계값이 등록되지 않은 재배 환경, 혹은 동기화 지연) 판단을 보류하고 그대로 리턴합니다.
2. 조회에 성공하면, 임계값 초과 여부와 무관하게 **모든** 측정값을 InfluxDB에 저장합니다. (자세한 내용은 [04_알림및외부연동/01_InfluxDB_저장](../04_알림및외부연동/01_InfluxDB_저장.md))
3. 등록된 `Rule` 목록(`List<Rule>`, Spring이 `@Component`로 등록된 구현체를 자동으로 주입)을 순회하며, `supports(dto)`가 `true`인 Rule에 대해서만 `evaluate(dto, thresholdInfoDto)`를 호출합니다.

## 2. Rule 인터페이스

```java
public interface Rule {

    boolean supports(SensorDataDto dto);

    void evaluate(SensorDataDto sensorData, ThresholdInfoDto thresholdInfo);
}
```

- `supports`: 이 센서 데이터에 대해 이 Rule을 적용할지 여부
- `evaluate`: 임계값 정보를 바탕으로 실제 판단 및 후속 처리(알림 발행, 액추에이터 제어 등)를 수행

## 3. 등록된 Rule 목록

| Rule | supports 조건 | 역할 |
|---|---|---|
| [`ThresholdExceededRule`](./01_ThresholdExceededRule.md) | 항상 `true` (모든 센서 데이터) | 임계값 초과/복귀 감지 → RabbitMQ 알림 발행 |
| [`ActuatorControlRule`](./02_ActuatorControlRule.md) | `SensorType.contains(sensorType)`인 경우 (`TEMPERATURE`/`HUMIDITY`/`CO2`/`LIGHT`) | 평균값·지속시간 기준으로 액추에이터 ON/OFF 결정 → Feign으로 제어 명령 전송 |

두 Rule은 서로 독립적으로 평가되며, 하나의 센서 데이터에 대해 둘 다 실행될 수 있습니다. (실행 순서는 Spring이 주입하는 `List<Rule>`의 순서를 따르며, 별도의 우선순위(`@Order`)는 지정되어 있지 않습니다)
