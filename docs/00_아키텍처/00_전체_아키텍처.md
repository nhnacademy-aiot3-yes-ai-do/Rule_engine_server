# 00. 전체 아키텍처

버섯 재배 환경의 센서(온도, 습도, CO2, 조도)가 MQTT로 데이터를 발행하면, **Collector**가 이를 구독하여 파싱·검증한 뒤 이벤트로 **RuleEngine**에 전달합니다.
RuleEngine은 전달받은 데이터를 해당 재배 환경에 설정된 임계값과 비교하여 정상/이상 여부를 판단하고, 판단 결과에 따라 InfluxDB 저장, RabbitMQ 알림 발행, 액추에이터 제어(HTTP)를 수행합니다.

이때 Collector의 검증과 RuleEngine의 판단에 사용되는 재배 환경·센서 정보(임계값 포함)는 **Registry** 모듈이 관리합니다. 이 정보의 원본은 `cultivation-server`가 갖고 있으며, Registry는 RabbitMQ 이벤트 구독과 애플리케이션 기동 시 스냅샷 동기화(HTTP)를 통해 우리 쪽 Redis에 캐시해두고 조회 용도로 사용합니다.

## 구간별 설명

### 1. Collector (MQTT 구독 → 파싱 → 검증 → 이벤트 발행)

센서로부터 발행되는 데이터를 MQTT로 구독하고, 파싱·검증을 거쳐 통과한 데이터를 `SensorDataReadyEvent`로 발행합니다.

- 참고: [01_Collector](../01_Collector)

### 2. Registry (재배 환경·센서 정보 관리)

Collector의 검증과 RuleEngine의 판단에 필요한 재배 환경별 임계값 정보(`ThresholdInfo`)와 센서 등록 정보(`SensorInfo`)를 Redis에 유지합니다. `cultivation-server`가 발행하는 RabbitMQ 이벤트를 구독해 변경분을 실시간 반영하고, 애플리케이션 기동 시에는 `cultivation-server`의 스냅샷 API를 호출해 기존에 등록되어 있던 전체 데이터를 한 번에 채워 넣습니다.

- 참고: [02_Registry](../02_Registry)

### 3. RuleEngine (판단)

`SensorDataReadyEvent`를 수신하여, 센서 데이터의 `cultivationId`로 임계값 정보를 조회하고 등록된 `Rule` 목록을 순회하며 각 Rule의 판단 로직을 수행합니다. 현재 등록된 Rule은 두 가지입니다.

- `ThresholdExceededRule` : 임계값 초과/복귀를 감지해 알림을 발행
- `ActuatorControlRule` : 평균값과 지속 시간을 기준으로 액추에이터(히터, 가습기 등)를 켜고 끄도록 제어

- 참고: [03_RuleEngine](../03_RuleEngine)

### 4. 알림 발행 및 외부 연동

RuleEngine의 판단 결과는 두 갈래로 나갑니다. 모든 센서 값은 InfluxDB에 시계열 데이터로 저장되고, 임계값 초과/복귀 및 액추에이터 동작 결과는 RabbitMQ로 발행되어 알림 서비스가 소비합니다. 액추에이터 제어 명령 자체는 RabbitMQ가 아니라 `data-generator-server`에 대한 Feign(HTTP) 호출로 전달됩니다.

- 참고: [04_알림및외부연동](../04_알림및외부연동)

## 전체 흐름

```text
[ cultivation-server : 재배 환경(임계값) 및 센서 등록/수정/삭제 ]
        │
        ├── (기동 시 1회) Feign GET snapshot ─────────────────┐
        │                                                   ▼
        └── (실시간) AMQP Publish → @RabbitListener 수신 → [ Redis (ThresholdInfo / SensorInfo) ]
                                                            ▲
                                                            │ (조회)
[ Sensor (온도/습도/CO2/조도) ]                                │
        │ (MQTT Publish)                                    │
        ▼                                                   │
[ Collector ]                                               │
    1. MQTT 토픽 구독 (mushroom/#, application/#)             │
    2. 토픽·페이로드 파싱 → SensorDataDto                       │
    3. 관리 대상 센서 타입 / 등록 여부 검증 (Redis 조회) ────────────┘
        │ (ApplicationEvent, @Async)
        ▼
[ RuleEngine ]
    1. cultivationId로 임계값 정보 조회 (없으면 판단 보류)
    2. InfluxDB에 원본 측정값 저장
    3. 등록된 Rule 순회
        ├─ ThresholdExceededRule → 임계값 초과/복귀 시 RabbitMQ 알림 발행
        └─ ActuatorControlRule  → 평균값·지속시간 기준으로 액추에이터 ON/OFF 결정 → Feign으로 data-generator-server에 명령 전송 → 결과를 RabbitMQ로 알림 발행
```
